# Supabase 공유 저장 전환

## 적용 순서

1. 기존 프로젝트 `gfbkmbfmojioocevnpvq`의 SQL Editor에서 `supabase/upgrade-v2.sql`을 실행합니다. 기존 schema.sql은 다시 실행하지 않습니다.
2. `select public.planner_health();` 결과의 schema_version이 2인지 확인합니다.
3. cloud.js를 포함한 새 버전을 Vercel에 배포합니다. DB가 버전 1이면 새 앱은 로그인 단계에서 업데이트 안내를 표시합니다.
4. 승인된 교사 계정과 학생 계정으로 아래 절차를 검증합니다.

## 교사와 학생 검증

1. 교사로 로그인해 새 과제를 등록합니다. 대상은 예를 들어 2학년 2반과 파이로 선택합니다.
2. 별도 브라우저에서 해당 반 학생 또는 파이 학생으로 로그인합니다. 공지가 조회되고 플래너에도 자동 표시되는지 확인합니다.
3. 이미 로그인한 학생 화면은 20초마다 갱신됩니다. 화면 위 새 소식 확인 버튼으로 즉시 확인할 수도 있습니다. 편집창을 열었을 때는 자동 갱신하지 않습니다.
4. 다른 반·동아리 학생에게는 공지가 표시되지 않아야 합니다.
5. 학생이 완료, 플래너 제목·날짜 수정, 제거를 한 뒤 다른 브라우저로 같은 계정에 로그인해 같은 상태인지 확인합니다.
6. 개인 일정 추가·수정·삭제, 원본 공지 수정·삭제와 1MB 이하 첨부파일 조회를 확인합니다.

## 저장 및 권한

- 공지와 그룹은 작성 교사가 관리합니다. 18개 반과 12개 동아리는 공통 대상 키로 제공합니다.
- 반·동아리는 profiles에 가입 당시 값으로 저장합니다. 사용자가 Auth 메타데이터만 바꿔도 DB의 소속은 바뀌지 않습니다.
- 초기 가입 때 학년·반이 없었던 이전 학생 계정은 처음 한 번만 학년·반을 보충할 수 있습니다.
- 완료 상태, 개인 일정, 과제 플래너 수정값은 사용자 ID별로 저장하고 RLS로 보호합니다.
- 가입 또는 로그인만으로 교사 권한이 생기지 않습니다. 관리자가 profiles.role을 지정합니다.
- 예전 브라우저 예시 데이터는 서버에 자동 업로드하지 않습니다. 기존 로컬 저장값은 삭제하지 않습니다.
- 이메일 인증 설정을 사용하므로 실제 메일 발송 서버 설정이 별도로 필요할 수 있습니다.

## 개발 검증

`node --test model.test.mjs auth.test.mjs connection.test.mjs agenda.test.mjs audience.test.mjs signup-profile.test.mjs clubs.test.mjs cloud.test.mjs`

PostgreSQL 통합 검증은 임시 의존성을 설치한 뒤 실행합니다.

`pnpm add @electric-sql/pglite@0.5.13 --dir .scratch/dbtest`

`node tests/cloud.integration.mjs`

통합 검증은 로컬 PostgreSQL 엔진에서 교사/학생/익명 역할을 바꾸며 수행합니다. 운영 계정이나 이메일을 만들지 않으며 운영 DB 검증을 대신하지는 않습니다.
