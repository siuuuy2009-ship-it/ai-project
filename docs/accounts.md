# 계정 가입 및 확인

`index.html`의 첫 화면에서 학생 또는 교사 유형을 선택해 가입하고 로그인합니다.
비밀번호는 Supabase Auth로 전송되며 앱의 브라우저 저장소에는 저장하지 않습니다.
현재 로그인은 열린 페이지에서만 유지됩니다. 새로고침 후에는 다시 로그인합니다.

## 이메일 인증

Supabase Authentication의 URL Configuration에서 Site URL을 실제 Vercel 서비스 주소로 지정하세요.
회원가입 인증 메일의 링크를 누른 다음 앱으로 돌아와 로그인합니다.
실제 메일 발송, 인증 후 로그인은 본인의 테스트 계정으로 확인해야 합니다.

## 교사 승인

교사로 가입해도 DB의 역할은 기본적으로 student입니다.
가입 시 `requested_role`은 신청 정보일 뿐 접근 권한으로 사용하지 않습니다.
관리자는 Authentication > Users에서 가입 이메일과 User UID를 확인하고,
실제 교사임을 확인한 계정에 한해서 Table Editor > profiles에서 같은 id 행의 role을 teacher로 변경합니다.
학생이 직접 역할을 변경할 권한은 부여하지 않습니다. 기존 schema.sql을 다시 실행할 필요는 없습니다.

## 현재 범위

학생 가입에는 학년, 반, 학번이 필수이고 동아리는 선택입니다. 여러 동아리는 쉼표로 구분합니다.
Supabase Auth의 user_metadata에 grade, classroom, student_number, clubs로 저장합니다.
별도 SQL 실행은 필요하지 않습니다. 새 브라우저의 첫 로그인에서 이 정보를 플래너에 적용하며,
이미 이 브라우저에서 수정해 저장한 프로필은 덮어쓰지 않습니다.
이 값은 자기 신고 정보이며 DB 그룹 가입/접근 권한 판정에 사용하지 않습니다.

가입과 로그인은 Supabase Auth 및 profiles 조회에 연결되어 있습니다.
기존 공지와 일정은 계정별로 분리된 브라우저 저장 방식이며 아직 서버 공유 저장이 아닙니다.
기존 체험 데이터는 삭제하지 않습니다. 계정별 저장 키로 이동하므로 기존 익명 체험 저장과 구분됩니다.

검증 항목: 학생 가입/메일 인증/로그인, 교사 가입/승인 전 차단/승인 후 로그인,
잘못된 비밀번호, 비밀번호 확인 불일치, 로그아웃, 다른 계정 로그인 후 데이터 분리.
